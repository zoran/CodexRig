# UI/UX Review

Read-only review of the affected experience; no redesign, product decisions or destructive user
actions. Read the user's intent, established requirements/design and actual shared consumers.
Repairs within the existing direction need no extra approval ritual; material visual-language,
navigation, information architecture or central-interaction changes retain their user decision gate.

Inspect a representative rendered task from entry through completion/recovery, with realistic
loading, empty, partial, error, validation, success and disabled states. Compare hierarchy,
legibility, language, spacing and component behavior with established intent. Trace shared changes
into consumers; personal aesthetic preference is not a defect.

Choose risk-bearing mobile/tablet/desktop conditions under
[multi-device policy](../../../instructions.md#multi-device-experience): reflow, localized/long
text, zoom, keyboard/focus, touch/pointer, semantics, accessible names, contrast and reduced motion.
Constrained loading must still permit task completion. Hidden content, tiny text and per-screen
patches do not repair a shared layout defect.

Record target/build and viewing/input conditions. Source or screenshots can support limited review
but do not prove interaction. New UI needs a concrete confirmed direction before it spreads;
existing UI does not reopen discovery. Route changed copy, raster assets and public search to their
specialist skills and reuse the evidence; no universal browser/screenshot service or visual archive
is required.

Return the affected flow/state, evidence, user impact, intent boundary and smallest proving recheck.
Separate defects, missing observations and optional suggestions. Implementation belongs to the
existing authorized owner; `$task-quality` composes acceptance.
